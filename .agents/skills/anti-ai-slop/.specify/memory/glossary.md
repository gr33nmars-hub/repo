# Glossary

| Term | Meaning | Required Use |
|---|---|---|
| AI slop | Visible output quality failure caused by generic, unsupported, over-smoothed, or template-like patterns. | Use for artifact quality, not authorship claims. |
| AI-smell risk | A review signal that resembles common AI-generated output patterns but is not proof of origin. | Pair with false-positive checks. |
| Output contract | The audience, purpose, medium, constraints, and success condition for an artifact. | Define before critique. |
| Specificity input | Context needed to make an output fit the user, product, domain, or decision. | Request or infer conservatively. |
| Evidence-to-revision | A trace from visible evidence to pattern category, impact, fix, replacement, and verification. | Required in review templates. |
| Coherence gate | A validator or checklist that checks consistency across requirements, tasks, docs, and implementation. | Run before delivery. |
| Dependency justification | Recorded reason for adding a package, action, scanner, or external tool. | Required before dependency additions. |
| Architecture boundary | A documented ownership line that prevents policy, validation, and workflow code from blurring together. | Enforced by validators. |
