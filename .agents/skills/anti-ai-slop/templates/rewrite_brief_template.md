# Rewrite Brief Template

Use this when converting a generic output into a purpose-built version.

```md
# Rewrite Brief

## Original problem

[Describe the generic pattern or failure.]

## Target output

- Audience:
- Purpose:
- Medium:
- Tone:
- Length:
- Must include:
- Must avoid:

## Specificity inputs

- Product / topic:
- User / buyer / reader:
- Situation:
- Constraint:
- Proof or evidence:
- Real examples:
- Brand vocabulary:
- Source material:
- User terminology:
- Locale / register:
- Product, UI, data, or code context:
- Required citations, screenshots, tests, or references:

## Missing-context handling

| Missing input | Impact on revision | Action |
|---|---|---|
|  |  | Ask user / make safe assumption / mark cannot revise reliably |
|  |  |  |

Use:

- `Ask user` when the missing input changes the core claim, compliance posture, audience, or product behavior.
- `Make safe assumption` when the revision can proceed with a clearly labeled, low-risk assumption.
- `Cannot revise reliably` when the output needs source material, data, screenshots, legal/security facts, or code context that is unavailable.

## Pattern-to-revision matrix

| Evidence | Smell category | Why it fails the contract | Specificity input needed | Revision instruction | Replacement example | Verification criterion |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

## Rewrite rules

1. Start with the actual problem, not a broad trend.
2. Replace generic verbs with domain-specific verbs.
3. Add concrete nouns, examples, and constraints.
4. Keep structure only where it improves scanning or decision-making.
5. Remove unsupported claims.
6. End with a specific action, decision, or implication.

## Deliverable

[Paste the revised output here.]
```
