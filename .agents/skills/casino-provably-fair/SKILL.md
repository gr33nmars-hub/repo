# Provably Fair & Casino Game Engine Skill

This skill guides the design, implementation, and academic defense of a **Provably Fair** gambling system.

---

## 1. Academic & Cryptographic Architecture

### Core Mechanism: HMAC-SHA256 Commitment Scheme
In online gambling, "Provably Fair" ensures that the server cannot alter the outcome after the player places a bet, and the player cannot predict the outcome in advance.

1. **Server Seed ($S_{server}$)**: 64-character cryptographic random hex string generated on the backend (`secrets.token_hex(32)`).
2. **Server Seed Hash ($H_{server}$)**: $\text{SHA256}(S_{server})$ published to the client **before** the bet is placed. This commits the server to the outcome without revealing $S_{server}$.
3. **Client Seed ($S_{client}$)**: String provided by the user (or generated by the client browser). The server cannot manipulate this.
4. **Nonce ($N$)**: Integer counter ($0, 1, 2, \dots$) incrementing with each bet made with this seed pair.
5. **Outcome Hash**:
   $$\text{HMAC-SHA256}(\text{key}=S_{server}, \text{msg}=S_{client} + ":" + N)$$
6. **Seed Rotation & Verification**:
   When the player rotates seeds, the server reveals the unhashed $S_{server}$. The player verifies:
   - $\text{SHA256}(S_{server}) == H_{server}$ (pre-image check)
   - Recomputes the game outcome for every nonce using the revealed seed.

## 2. Mathematical Models for Casino Games

### A. Crash Game
- **House Edge**: $1\%$ (RTP = $99\%$) or $3\%$ (RTP = $97\%$).
- **Algorithm**:
  1. Take the first 52 bits (13 hex characters) of HMAC:
     $$h = \text{int}(HMAC[:13], 16)$$
  2. Compute probability float $e = 2^{52}$:
     If $h \pmod{33} == 0$ (approx. $3\%$ instant crash rate), multiplier is $1.00\times$.
  3. Otherwise:
     $$\text{multiplier} = \max\left(1.00, \left\lfloor \frac{100 \times 2^{52} - h}{2^{52} - h} \times 0.01 \times 100 \right\rfloor / 100\right)$$
  - Alternatively:
     $$M = \max\left(1.00, \frac{0.99}{1 - \frac{h}{2^{52}}}\right)$$

### B. Provably Fair Dice ($0.00 - 99.99$)
- 4 bytes (8 hex characters) converted to integer:
  $$h = \text{int}(HMAC[:8], 16)$$
  $$\text{roll} = (h \pmod{10000}) / 100.0$$

### C. European Roulette ($0 - 36$)
- Single zero European wheel has 37 pockets ($0$ to $36$):
  $$h = \text{int}(HMAC[:8], 16)$$
  $$\text{pocket} = h \pmod{37}$$
- **RTP**: $\frac{36}{37} \approx 97.3\%$ across standard bets.

### D. Mines Game ($5 \times 5$ Grid, 25 Tiles)
- Fisher-Yates Shuffle using HMAC output as cryptographic PRNG stream:
  - Generate 25 tiles (e.g. 3 mines, 22 gems).
  - Shuffle index $i$ from 24 down to 1 using successive bytes from HMAC.

### E. Blackjack & Deck Shuffle
- 52 cards (or multi-deck 312 cards for 6 decks).
- Unbiased Fisher-Yates shuffle using sequential chunks of HMAC-SHA256 (re-hashing with round index if HMAC bytes are exhausted).
- Dealer stands on hard 17, hits on soft 17 (or standard university rule).

## 3. Reference Implementation (Python / FastAPI)

```python
import hashlib
import hmac
import math
import secrets
from typing import Tuple

class ProvablyFairEngine:
    @staticmethod
    def generate_server_seed() -> Tuple[str, str]:
        """Returns (server_seed, server_seed_hash)."""
        server_seed = secrets.token_hex(32)
        server_hash = hashlib.sha256(server_seed.encode("utf-8")).hexdigest()
        return server_seed, server_hash

    @staticmethod
    def compute_hmac(server_seed: str, client_seed: str, nonce: int) -> str:
        message = f"{client_seed}:{nonce}".encode("utf-8")
        return hmac.new(server_seed.encode("utf-8"), message, hashlib.sha256).hexdigest()

    @classmethod
    def crash_multiplier(cls, server_seed: str, client_seed: str, nonce: int, house_edge: float = 0.03) -> float:
        h = cls.compute_hmac(server_seed, client_seed, nonce)
        # Take first 13 hex chars (52 bits)
        sub_hash = int(h[:13], 16)
        e = 2**52
        
        # House instant crash probability (e.g., 33 -> ~3%)
        if sub_hash % int(1 / house_edge) == 0:
            return 1.00
            
        result = (100 * e - sub_hash) / (e - sub_hash)
        multiplier = math.floor(result) / 100.0
        return max(1.00, multiplier)

    @classmethod
    def dice_roll(cls, server_seed: str, client_seed: str, nonce: int) -> float:
        h = cls.compute_hmac(server_seed, client_seed, nonce)
        sub_hash = int(h[:8], 16)
        return round((sub_hash % 10000) / 100.0, 2)
```

## 4. Academic Defense & Statistical Verification (Monte Carlo)

To demonstrate rigorous engineering to professors:
1. **Convergence Test**: Run $N = 100,000$ simulated bets.
2. Calculate empirical RTP:
   $$\text{RTP}_{emp} = \frac{\sum \text{Payouts}}{\sum \text{Bets}} \times 100\%$$
3. Demonstrate that $\lim_{N \to \infty} \text{RTP}_{emp} = \text{RTP}_{theor} \pm \epsilon$.
4. Provide client-side verification UI with a standalone verifier tab where the user inputs `server_seed`, `client_seed`, `nonce` and confirms the result.
