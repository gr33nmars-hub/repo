# ADR-004: Версионированные правила раунда

## Статус

Accepted

## Контекст

Выплата объяснима только вместе с правилами, по которым она рассчитана. Правила слотов, рулетки и blackjack могут измениться после сохранения старой истории.

## Рассмотренные варианты

| Вариант | Выгода | Цена |
|---|---|---|
| Хранить rule version, fingerprint и нужные данные исхода | Старый результат можно проверить после изменения текущих правил. | Снимок увеличивает размер истории и требует независимого verifier. |
| Проверять историю текущей конфигурацией | Минимальный формат данных. | Изменение конфигурации делает старые результаты неоднозначными. |

## Решение

Для новых раундов сохранять `rule_version`, fingerprint снимка правил и machine-readable outcome; verifier не должен вычислять выплату через тот же production payout код. Полностью старые записи без этих полей отображаются как `legacy-unverified`. Если метаданные присутствуют, verifier проверяет их целостность и сохранённый исход даже у roulette/blackjack записей без seed proof; повреждённые записи отображаются как `invalid`.

Для новых раундов всех игр также используется общий SHA-256 commitment server seed. Использованный seed и client seed сохраняются в proof после завершения; текущий seed раскрывается только после того, как соответствующий раунд завершён. Blackjack хранит proof и последовательность добора в активном snapshot. Это локальная проверка соответствия commitment и воспроизведения результата, а не доказательство честности приложения.

## Последствия

- Изменение выплаты или правил требует новой версии.
- Сохраненные старые результаты читаются без миграции их payout.
- Любой verifier failure должен быть виден как invalid, а не как успешная проверка.
- Корректные старые roulette/blackjack записи без seed proof отображаются как `legacy-unverified` после проверки метаданных, исхода и выплаты.

## Пересмотреть, если

Размер профиля заметно вырастет или формат исхода перестанет позволять воспроизводить заявленные выплаты.
